# 阶段二小步骤清单

- 步骤 1：请求 ID 与结构化日志骨架 —— 为所有 HTTP 入口生成/透传 `X-Request-ID`，输出包含 request_id、路径、状态码、耗时、脱敏 session_id 的 JSON 日志，验收 `/chat` 与 `/chat/stream` 可按 request_id 串联（对应 P2-1）。
- 步骤 2：统一错误响应与异常兜底接入点 —— 定义统一错误体与错误分类，增加全局异常处理，并在工具/LLM 调用边界建立可替换的异常包装点（不实现重试与降级），验收异常请求返回结构化 500 且不泄露堆栈与密钥（对应 P2-2）。
- 步骤 3：健康检查与基础运行防护 —— 增加 `/healthz`（返回服务状态、记忆后端类型、版本），提供可配置 CORS 白名单与进程内基础限流，验收健康检查 200、跨域策略生效、超限返回 429（对应 P2-3）。
- 步骤 4：NDJSON 流式协议字段预留 —— 在保持 `delta` / `done` 兼容的前提下新增 `meta` 事件与 `agent`、`tool_calls`、`latency_ms`、`cache_hit` 可选字段，并补充协议样例，验收旧前端渲染不受影响、新字段可被解析（对应 P2-4）。
- 步骤 5：Webhook 验签策略与配置占位 —— 输出各平台验签策略、配置项与未配置时的明确行为（不实现真实签名算法），验收文档与配置占位可指导后续平台接入（对应 P2-5）。

说明：

- 步骤 1 是本清单确认后下一轮要输出 Prompt 的步骤。
- 步骤 2-5 均不包含多 Agent、Harness 运行时、Redis 双层缓存、评测压测等内容。
